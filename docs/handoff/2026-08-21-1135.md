## Session Objectives

本阶段的目标是完成 Runtime Inspector MVP 最关键的技术闭环：

```text
Tool Call → DSH subprocess spawn → root PID → process creation identity
```

范围限定为 Ticket 02：不修改 DSH core、不替换 PowerShell/subprocess provider、不接管进程生命周期；必须能被普通用户作为 Bundle 安装，并在并发 Tool Call、Code Mode、background/terminal 语义下保持安全归因。

## Problems Encountered and Decision Process

### Problem 1：只用 `internal/get` Proxy 在真实 stock path 捕获不到所有 spawn

#### Investigation

源码和 Stock DSH smoke 显示，PowerShell executor 的实际路径会动态读取 `ctx.subprocess.spawn`，但某些 consumer context 的读取发生在 `internal/get` 可观察 waterfall 之外。Proxy 单独测试可工作，但真实 native shell 路径仍可能绕过它。

#### Solutions Considered

- **A：修改 DSH core 增加 `subprocess/started`**：长期最自然，但当前 DSH 不向普通开发者开放 PR，不能作为安装即用 MVP 前提。
- **B：接管 PowerShell Provider**：可直接拿 PID，但会复制 sandbox、background、cancellation 和 terminal 语义，维护成本高。
- **C：替换/继承 subprocess provider**：能拿 PID，但 provider dispose/reload 可能终止全部受管进程，违反卸载不杀用户进程。
- **D：`internal/get` Proxy + local fallback**：保留透明 Proxy；当 pinned stock path 绕过 waterfall 时，仅包装真实 `LocalSubprocessRuntime` 的 `spawn`/`spawnTerminal` 方法。

#### Final Decision

采用 D。fallback 只有在 `active && verifiedAttributionEnabled` 且 provider class 名为 `LocalSubprocessRuntime` 时才允许安装；不接管 ownership，卸载时恢复原 descriptor。

#### Rationale / Future Implications

这是在“无 core PR、普通用户安装即用”和“真实 stock path 可捕获”之间的最小折中。未来若 DSH 提供稳定的 provider-neutral started event，可以移除 fallback，只保留公开 seam。

### Problem 2：同一个 root 被登记两次

#### Investigation

一次 smoke 中发现相同 PID 出现两条 ProcessOrigin。日志顺序证明同一个 handle 同时经过：

1. method-level fallback；
2. `internal/get` non-mutating Proxy。

两层都会调用 `observeHandle()`，所以这是重复观察，不是 PID extraction 失败。

#### Final Decision

`ProcessOriginRegistry.record()` 在写入前按 exact handle identity 去重；同一 handle 只保留第一次 origin，不按 PID 去重，避免不同 spawn 复用或 PID reuse 被错误合并。

### Problem 3：临时诊断输出导致错误的“空 Registry”现象

#### Investigation

最初 probe 把 debug/origins 文件写入 `DSH_HOME`。Stock DSH 的 Profile watcher 会触发 Bundle reload，随后创建新的 registry；因此父测试有时读到了新实例的空 registry。与此同时，子进程日志已证明：

```text
spawn → handle.pid = 12980
→ ALS frame present
→ OpenProcess 成功
→ GetProcessTimes 返回 1
→ WaitForSingleObject = 258 (WAIT_TIMEOUT)
→ registry.record accepted
```

实际记录的 creation identity 为 `134317548710614515`。

#### Final Decision

确认 PID extraction 和 Win32 identity 链路本身可靠；清理运行时诊断日志，并将 smoke 结果写到 DSH_HOME 外的临时结果目录，避免测试输出触发 profile reload。该问题不是生产 Registry 逻辑缺失。

### Problem 4：代码审查发现 fallback 安全边界不足

#### Investigation

审查发现三个风险：降级/未知 provider 仍可能被 patch；插件 dispose 后迟到 Tool Call 可能重新安装 wrapper；`spawn` 已安装而 `spawnTerminal` 安装失败时可能留下半成品 patch。

#### Final Decision

已补齐：

- `observationAllowed()` 检查 active 和 compatibility gate；仅允许 `LocalSubprocessRuntime`。
- compatibility drop 和 dispose 调用 `disableProviderPatches()`。
- descriptor preflight 拒绝不可安全修改的 accessor/non-writable 情况。
- 双方法安装具备事务性；后一个 descriptor 失败时恢复前一个 descriptor。
- `internal/get`、`internal/service`、Session event 和 frame parsing 的异常均 containment，不改变原 provider/Session 行为。
- 增加 Proxy `defineProperty` 失败注入测试，覆盖真实 rollback catch path。

## Key Decisions and Context

- 不修改 DSH core，不依赖私有 fork，不替换 provider，不调用 provider dispose 清理用户进程。
- Runtime Inspector 是只读观察者；观察失败不能使成功的 Tool Call 失败。
- Verified attribution 必须同时具备有效 PID、creation identity 和完整 Session/Agent/Turn/Step/Call context。
- `rootPid` 不是靠命令行、目录、端口或事后扫描猜测，而是在真实 `spawn` 返回 handle 后立即取得。
- Process origin 是当前 DSH 运行期 memory-only 数据，root 退出后仍保留，供后续 ancestry matching 使用。
- command 在进入 registry 前脱敏并限长；不读取环境变量，不保留 raw argv。
