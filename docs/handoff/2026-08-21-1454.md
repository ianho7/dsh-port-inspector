## Problems Encountered and Decision Process

### Problem 1: How to expose current-session detail without leaking another Session

#### Investigation

`ProcessOrigin` contains Session, Agent, Turn, Step, Call, command, workdir, and optional Job/Terminal owner data. Passing scanner rows or origins directly to a model-facing Tool would disclose another Session's command and project history and could expose internal action identifiers.

#### Solutions Considered

1. Expose all origins to every Tool caller.
   - Simple and useful for debugging.
   - Violates the Ticket 06 privacy boundary and risks cross-Session disclosure.

2. Hide all origin details from the Tool.
   - Strong privacy and simple safety model.
   - Removes the core value of helping an Agent reason about its own DSH work.

3. Project by the executing Agent's Session identity.
   - Preserves full redacted attribution for the current Session and a coarse ownership signal for another Session.
   - Requires an explicit projection layer and careful omission of owner/action identifiers across the privacy boundary.

#### Final Decision

Use option 3. A matching current Session receives bounded redacted attribution. A matching other Session receives only `ownership: another-dsh-session`; its Session ID, Call history, command, workdir, project, and lifecycle owner ID are omitted. Unattributed rows remain visible with `unattributed` confidence/ownership.

#### Rationale

This preserves the MVP's diagnostic value while making the model-facing Tool a read-only information boundary. Managed-owner authority is not inferred from a heuristic: lifecycle owner information is exposed only for a verified ancestry match.

### Problem 2: DSH output schema contract differs from parameter schema syntax

#### Investigation

The first Tool schema draft used `required: true` on individual output properties, matching the author-facing `defineTool` parameter style. Inspection of the Stock DSH tool implementation showed that raw `ctx.tools.register()` output schemas use standard JSON Schema object-level `required: string[]` arrays.

#### Final Decision

Convert the Tool output schema to standard raw JSON Schema: object-level `required` arrays, `additionalProperties: false`, and scalar `enum` constraints. Make Tool execution asynchronous to match the DSH `ToolDefinition` contract.

#### Evidence

The corrected schema compiles, passes the local schema-shape regression test, and the complete deterministic suite passes. A permitted real Stock DSH registration smoke is still required because the current environment blocks the existing fixture before Bundle startup.

## Key Decisions and Context

- The plugin is observational and does not own DSH processes. Unload only removes observers, Tool registration, and lifecycle state.
- Verified attribution requires PID plus canonical decimal FILETIME creation identity and a complete, unambiguous, cycle-free ancestry chain.
- Inferred attribution is diagnostic only and never grants managed-owner authority.
- Managed Job/Terminal shutdown uses DSH owner APIs and never escalates to PID/process-tree termination.
- External termination is a separate, explicit, same-user, single-PID, identity-fenced action and is never exposed as a capability of `port_list`.
- `port_list` is model-facing and read-only. It receives no arguments, exposes no action callback, is bounded to 128 rows, and marks scan incompleteness rather than treating an empty result as proof.
- Current-session attribution is full but bounded/redacted; other-session attribution is coarse by design. Environment blocks and secrets are not collected.
- Origins are memory-only for the current DSH run. Degraded mode uses no origins to avoid stale verified claims.
- The repository currently has no commit containing Ticket 06. Preserve the existing Ticket 04/05 worktree changes when committing or reviewing.
