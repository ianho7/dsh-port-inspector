# 02: 开发环境与其他监听分流

**What to build:** 将明确识别的开发运行时和本地基础设施归入“开发环境”，把没有开发依据的系统服务和桌面应用收进默认折叠的“其他监听”；搜索仍覆盖全部 inventory，“全部监听”恢复完整系统视图。

**Blocked by:** 01: 当前项目开发端口主路径.

**Status:** resolved

- [x] 已知开发运行时、框架和基础设施在有明确 executable、项目、Session 或已脱敏命令证据时归入 `development-environment`。
- [x] 常见端口号不能单独建立开发相关性；证据不足时稳定归入 `other`。
- [x] System、Service Host 和无关桌面应用默认不出现在开发端口分组，并通过“其他监听”计数与折叠入口保持可发现。
- [x] 搜索端口、PID、应用或项目时会命中折叠项，并明确说明搜索覆盖全部监听。
- [x] “全部监听”展示完整 Host inventory，“开发端口”计数不重复计算固定项。
- [x] 分组、折叠、搜索、空结果与选择保持行为测试通过。

实现说明：Host 仅依据 Session、项目路径、可执行文件和已脱敏命令证据判断开发相关性；端口号不参与分类。Browser 默认展示当前项目与开发环境，将其他监听折叠但纳入全局搜索和“全部监听”。Host 与 Client 聚焦测试及严格类型检查已通过。

## Answer

开发环境与其他监听已经分流。System、Service Host、桌面应用和未知监听默认进入“其他监听”；搜索和“全部监听”仍可访问完整 inventory。项目目录变化会触发重新请求，避免沿用旧项目上下文。
